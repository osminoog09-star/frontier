# FRONTIER - анализ стройки и зон по RimWorld-модели

Дата: 2026-06-05  
Статус: design/architecture slice после фидбека игрока.

## Главный вывод

Последний UI-срез v2.18 сделал удобнее панель Architect, но не решил главное: у нас строительство всё ещё слишком часто является списком "готовых зданий", а не системой приказов, зон, помещений и рабочих мест.

Нужная модель:

- Architect - это не магазин зданий, а центр приказов: строить, ставить мебель/станки, рисовать зоны, назначать области работ, сносить, планировать.
- Большая часть "экономики" должна жить не в magic-building, а в связке: помещение + объект/станок + зона + склад + работа пешки.
- Зоны должны быть полноценным gameplay-слоем, не декоративной заливкой.
- Размещение объектов должно поддерживать разные snap-режимы: по клетке, по половине клетки, свободно внутри клетки, по стене/проёму.

## Что важно в RimWorld-подходе

1. Architect разделён по смыслу.
   - Структуры: стены, двери, заборы, колонны.
   - Производство: станки/рабочие места.
   - Мебель: кровати, столы, стулья, свет, декор.
   - Полы: рисуются кистью.
   - Зоны: склад, выращивание, домашняя зона, разрешённые области, крыша, план.
   - Приказы: добыть, рубить, охотиться, тушить/ремонтировать, отменить.

2. Здание не равно профессия.
   - Шахта в RimWorld-смысле - это не "поставил шахту и она печатает руду".
   - Правильнее: есть помеченные жилы/камни/зона добычи, пешка с работой mining идёт и копает.
   - Для глубокой шахты можно требовать помещение/станок/шахтный узел, но добыча всё равно идёт из назначенной области.

3. Комната определяется стенами, дверями, крышей и содержимым.
   - Кухня = закрытая комната + плита/кухонный станок.
   - Мастерская = закрытая комната + верстак/кузня.
   - Спальня = кровати в комнате.
   - Склад = stockpile-zone или помещение с storage-зоной.
   - Название комнаты появляется из состава, а не из кнопки "построить кухню".

4. Зоны рисуются областями.
   - Grow zone: где сеять/жать.
   - Stockpile zone: где хранить и какие фильтры.
   - Allowed area: где пешкам можно ходить.
   - Home area: где чинить/убирать/тушить.
   - Mining zone: где копать.
   - Roof zone: где строить/снимать крышу.
   - Plan zone: только разметка для игрока.

5. Размещение не обязано быть только тайл-в-тайл.
   - Стены/полы/зоны остаются тайловыми, потому что они влияют на pathfinding и комнаты.
   - Мебель/станки могут иметь footprint в тайлах, но точное положение и поворот должны быть отдельными.
   - Декор/лампы/стулья могут стоять внутри клетки с sub-tile координатой.

## Что у нас сейчас

### Уже близко

- Есть `G.buildings` с чертежами, доставкой материалов и строительной работой.
- Есть стены/ворота/полы/комнаты/крыша.
- Есть `G.zones`: grow, stockpile, allowed.
- Есть grow-zone farming и stockpile-zone hauling.
- Есть room detection: `enclosedRoomAt()`, типы комнат, уют, крыша.
- Есть Architect UI с категориями и отдельной панелью приказов.

### Что неверно по модели

- `farm`, `mine`, `stockpile` ещё существуют как обычные buildings в `BUILDS`.
- `tryFarm()` работает от здания `farm`, хотя правильный основной путь уже должен быть grow-zone.
- `tryMine()` сначала ищет помеченные камни, но если их нет, использует здание `mine`, которое генерирует руду/золото из воздуха.
- `stockpile` есть и как здание, и как зона. Это раздваивает механику.
- `saloon`, `kitchen`, `lab`, `clinic`, `smithy` сейчас являются зданиями 2x2, а должны постепенно стать станками/объектами внутри комнат.
- Все buildings привязаны к `tx/ty` и `size`, то есть к квадратной сетке без поворота и sub-tile placement.

## Целевая модель данных

### 1. Объекты строительства

Вместо только `tx/ty/size`:

```js
{
  id,
  kind: 'wall' | 'door' | 'workbench' | 'furniture' | 'storage' | 'decor',
  type,
  x, y,              // точная позиция в тайлах, может быть 12.5
  tx, ty,            // кэш для совместимости/pathfinding
  w, h,              // footprint в тайлах
  rot,               // 0/90/180/270
  snap: 'tile' | 'half' | 'free' | 'wall',
  blueprint,
  done,
  materialsPaid,
  quality,
  hp
}
```

Старые сейвы нормализуются: `tx/ty/size -> x/y/w/h/rot`.

### 2. Зоны

Зона должна иметь тип, клетки, настройки, фильтры и роль в AI:

```js
{
  id,
  type: 'grow' | 'stockpile' | 'allowed' | 'home' | 'mine' | 'roof' | 'plan',
  cells: ['10,12', '10,13'],
  settings: {},
  filters: {},
  priority: 1
}
```

Главное правило: зона - это приказ/область, а не здание.

### 3. Комнаты

Комната должна стать отдельным вычисляемым слоем:

```js
{
  id,
  cells,
  buildings,
  zones,
  type,
  roofed,
  doorCount,
  stats: { space, beauty, cleanliness, comfort, wealth }
}
```

Тип комнаты выводится из содержимого:

- bed -> спальня / барак.
- stove/kitchen table -> кухня.
- smithy/workbench -> мастерская.
- lab bench -> лаборатория.
- medical bed/medicine storage -> клиника.
- stockpile zone -> склад.
- saloon furniture -> зал/место отдыха, но это уже Frontier-слой поверх общей модели.

## Как должна работать шахта по твоему примеру

Цель: не "поставил шахту 1x1", а сделал mining workflow.

1. Игрок строит помещение стенами, например 6x6.
2. Внутри ставит нужный объект: шахтная стойка/шахтный стол/подъёмник/инструментальный стеллаж.
3. Рядом или внутри рисует склад/зону хранения руды.
4. На карте рисует `Зона добычи` там, где нужно копать.
5. Пешка с работой Mining:
   - проверяет доступную `mine`-зону;
   - идёт к клетке зоны;
   - копает ресурс/камень/жилу;
   - создаёт ground stack;
   - hauling переносит stack в stockpile-zone.
6. Помещение 6x6 и станок дают бонус/разрешение:
   - без шахтного помещения можно копать вручную камни/жилы;
   - с помещением и стойкой можно вести стабильную разработку зоны быстрее/безопаснее;
   - склад рядом уменьшает таскание.

То есть "шахта" становится не зданием-производителем, а системой: room + station + mining zone + stockpile + jobs.

## Что переименовать/разделить в Architect

### Категории

1. Структуры
   - стены: дерево/камень/саман/будущие материалы.
   - дверь/ворота.
   - заборы, мешки, укрепления.

2. Производство
   - плита/кухонный стол.
   - кузня/верстак.
   - лабораторный стол.
   - шахтная стойка/инструментальный стеллаж.

3. Мебель
   - кровать, спальный мешок, стол, стул, декор.

4. Полы
   - дерево, камень, дорога.

5. Зоны
   - грядка.
   - склад.
   - добыча.
   - разрешённая зона.
   - домашняя зона.
   - крыша.
   - план.

6. Приказы
   - рубить.
   - добывать.
   - охотиться.
   - отменить.
   - снести.

Frontier-объекты вроде салуна/ранчо не должны быть первой линией в общей строительной системе. Они могут остаться позже как тематические станки/комнаты/сценарные постройки, но базовая модель должна быть универсальной.

## Порядок внедрения маленькими срезами

### Slice 1 - Architect taxonomy without gameplay break

- Переставить текущие кнопки по новой структуре.
- Не удалять старые id.
- Временно оставить старые buildings, но визуально отделить "зоны" и "объекты".
- Harness: кнопки существуют, buildMode старых ids не сломан.
- Browser smoke: категории/команды не перекрывают UI.

### Slice 2 - Mining zone foundation

- Добавить `ZONE_DEFS.mine`.
- Добавить кнопку `Зона добычи`.
- `tryMine()` должен предпочитать mine-zone и отмеченные rocks, а не здание `mine`.
- В mine-zone нельзя рисовать воду; можно рисовать rock/ore/землю по правилам.
- Harness: зона добычи создаёт ore stack, hauling увозит в stockpile-zone.

### Slice 3 - Deprecate magic mine building

- Кнопка `Шахта` становится не production-building, а mining station/шахтная стойка.
- Старые сейвы с `mine` нормализуются в station или остаются legacy-совместимыми.
- Стабильная добыча требует: mine-zone + доступный mining station в комнате или ручной режим с меньшей скоростью.
- Harness: старый save не падает, новая зона добывает без magic tick gold.

### Slice 4 - Stockpile building -> stockpile zone

- Склад-здание убрать из основной логики как обязательный storage.
- Главный склад = зона с фильтрами.
- Старый `stockpile` building в save превращать в stockpile-zone footprint.
- Harness: ресурсы на земле едут в zone; фильтры работают; старые сейвы сохраняются.

### Slice 5 - Farm building -> grow zone only

- `tryFarm()` либо удалить, либо сделать legacy fallback.
- Ферма в Architect становится `Грядка/Зона выращивания`.
- Если нужен объект - добавить "сарай/инструменты фермера" как бонус, а не генератор еды.
- Harness: grow zone производит food, старое farm-building не ломает save.

### Slice 6 - Room + station production

- Кухня/кузня/лаборатория становятся станками внутри комнат.
- Room type выводится из станков.
- Рецепты требуют станок + материалы из stockpile/ground stack.
- Harness: кухня в комнате готовит, без room работает хуже или не получает бонус.

### Slice 7 - Placement snap modes

- Добавить `x/y/rot/w/h/snap`.
- Для стен/полов/зон оставить tile-snap.
- Для мебели/станков добавить rotate + half/free snap.
- UI: переключатель snap mode и поворот.
- Harness: старые `tx/ty` нормализуются, новая мебель с `x=10.5` рендерится и не ломает pathfinding.

## Риски

- Save/load: нельзя просто удалить старые `farm/mine/stockpile`.
- Pathfinding: свободное размещение не должно ломать тайловый A*.
- Room detection: если объекты станут sub-tile, комнаты всё равно должны считаться по стенам/дверям тайлово.
- UI: нельзя снова превратить Architect в простыню. Команд должно быть больше, но панель должна оставаться компактной.
- Harness: каждый migration-slice должен иметь сценарий, иначе старые сейвы и текущие сценарии легко сломать.

## Следующий правильный маленький срез

Самый безопасный старт: **Mining zone foundation**.

Почему:

- Пользователь прямо привёл пример шахты.
- Уже есть `tryMine()`, marked rocks, stockpile-zone hauling и zones framework.
- Можно сделать без полного sub-tile placement.
- Это убирает самый неправильный magic-building: `mine` как 1x1 генератор руды/золота.

Definition of done:

- В Architect есть `Зона добычи`.
- Игрок рисует mining-zone.
- Пешка с Mining копает клетки зоны/камни и создаёт ore stack.
- Ore stack уезжает в stockpile-zone.
- Старое здание `mine` не падает в save/load, но новая система работает без него.
- Harness Scenario CR: mine-zone -> ore stack -> stockpile.
